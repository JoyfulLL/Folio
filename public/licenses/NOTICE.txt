MODIFICATION AND REPLACEMENT (LGPL version 3, section 4(d))
-----------------------------------------------------------
The Library is shipped UNMODIFIED. It is a standalone, lazily loaded
JavaScript chunk (js/heic-decoder-*.js) fetched only when a HEIC/HEIF file is
uploaded and the browser cannot decode it natively; it is not part of the
main application bundle. The exact upstream version is pinned in
package-lock.json, and the complete corresponding source of the Library is
available from the npm registry at that pinned version and from the upstream
repository above. For an exact, unmodified source copy run
`npm pack heic-to@1.6.7` and compare it with the integrity hash recorded in
package-lock.json. Folio's complete application source is available at
https://github.com/JoyfulLL/Folio.

You may modify the Library, reverse engineer it to debug such modifications,
and recombine or relink Folio with a modified, interface-compatible version
of the Library. Folio imposes no additional restriction on either activity.
The decoder is isolated in convertHeicByDecoder() in src/lib/heic.ts, so
replacing it with another implementation requires changing only that one
adapter function and rebuilding the frontend.

BUILDING WITHOUT ANY LGPL COMPONENT
-----------------------------------
    FOLIO_HEIC_DECODER=none npm run build

That build ships no LGPL code at all (a tiny stub replaces the decoder), so
the resulting artifact is pure MIT. In it, HEIC uploads work only in browsers
with native HEIC decoding (for example Safari on iOS/macOS); other browsers
receive a clear error message instead of a silently broken upload.

PATENT NOTE
-----------
HEIC images are commonly encoded with HEVC (H.265). LGPL v3 carries the
patent grant of GPL v3 section 11 from the Library's contributors, but HEVC
may also be covered by third party patent pools. When the browser decodes a
HEIC image natively, decoding is performed by the operating system vendor's
licensed codec instead of by the bundled Library.
